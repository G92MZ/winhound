What it is

WinHound is the Windows sibling of Longanizer. It parses Windows Event Logs (.evtx) into a single normalized events table (DuckDB, UTC) and lets you search, run Sigma, hunt living-off-the-land activity, rebuild process trees and produce a case report — all in a local web UI, offline.

Built for Sysmon-rich telemetry (SwiftOnSecurity-style configs) but ingests any channel (Security, System, PowerShell/Operational, TaskScheduler, …).

Install & run

pip install --break-system-packages -r requirements.txt
python run.py            # http://127.0.0.1:8000
  • evtx (Rust parser) and pysigma/maxminddb install from PyPI as prebuilt wheels.
  • Set the case file explicitly with DUCKDB_PATH=case.duckdb python run.py; otherwise a timestamped case is created under casos/ on first ingest.
Everything runs on the machine you launch it on. No cloud, no outbound calls except the optional GeoIP database download.

Load EVTX

On the Load tab you have three ways in:

  • Upload individual .evtx, a whole folder (the entire tree), or a .zip/.tar.gz — EVTX are found recursively, non-EVTX are skipped.
  • Server path: point to a folder/file/archive already on the server's disk — faster (no browser upload) and shows live progress (files + events).
  • Open a saved case: reopen a .duckdb from casos/ instantly, no re-ingest.

CLI equivalent:

python -m winhound.cli ingest C:\triage\  --db case.duckdb
python -m winhound.cli stats --db case.duckdb

~600–700 MB of EVTX ingest comfortably (Rust parser + bulk insert). EVTX timestamps are already UTC — no timezone handling needed.

Sample data included. 562 attack EVTX ship in samples/evtx-attack-samples.zip (Sysmon + Security/System/PowerShell/RDP/BITS/Defender and more channels). Unzip it and load the evtx-attack-samples/ folder, or point either loader straight at the .zip. Everything in this guide was tested against that dataset.

Interface & tabs

The top tab bar groups related views under parent tabs. Clicking a parent opens a sub-bar with its children:

  • AI ▾ — AI API · AI local · MCP
  • Sigma & LOL ▾ — Sigma rules · LOLBAS · LOLDrivers · LOLRMM · LOTTunnels · HijackLibs · Lookalike · ATT&CK matrix
  • Hunting ▾ — Proc tree · Logons · Persistence · PowerShell · Network

Standalone tabs stay on the main bar: Load Overview Explorer IOC sweep SQL Marks Help.

Data model

Each record maps to columns + an extra JSON blob + the full raw record:

AreaEVTX source → column
SystemTimeCreated→ts (UTC) · Channel→source · Provider→program · EventID→event/eid · Computer→host · Security.UserID→sid · Level→level
EventData (first-class)Image, CommandLine, ParentImage, OriginalFileName, Hashes, TargetFilename, ImageLoaded, DestinationIp, SourceIp, LogonType, user
EventData (rest)→ extra (JSON) — reach it with extra->>'FieldName' and turn it into a column in the Explorer
Whole record→ raw (JSON) for full inspection

First-class vs extra is only about speed (native column sorts/filters faster on huge data), not availability — every field is reachable.

Explorer & SQL

  • Search any text (IOC, IP, hash, command, Image). Multiple words = AND. Toggle regex. The Channel dropdown narrows the source.
  • Time range (global): the From/To (UTC) inputs in the toolbar apply to both search results and the full timeline — set a window once and every view respects it.
  • Context: click a row (or jump by #) to see ±N events around it on the timeline.
  • Copy full event: the first column of every row (Explorer, timeline, context, IOC and Network tables) is a ⧉ copy button that puts the full event JSON on your clipboard; the context header also has a ⧉ Copy event JSON button.
  • ＋ add to review: the Explorer, timeline and context rows carry this button too — one click marks the event pending in the Marks tab, the same fast "to review later" pile you build from the Sigma and Hunting views.
  • ⬇ CSV: export the currently loaded rows straight from Explorer, the timeline, Network and the IOC summary.
  • Columns panel: first-class columns plus every extra key (born hidden). Windows has hundreds of keys — use the filter box to find them, then click to show and sort.
  • SQL tab: free DuckDB over events; reach EventData with extra->>'Key'.
Fast on big cases. Only the visible columns are rendered — hidden extra-JSON keys are no longer emitted as empty cells. Long cell values are truncated with the full value on hover, the default page size is 500 rows, and the time-window context is capped so the UI stays responsive even with hundreds of thousands of events.

IOC sweep

A standalone tab for triaging a list of indicators at once. Paste your IOCs — one per line, or comma / semicolon separated — mixing IPs, hashes, file names, domains and users, and sweep the whole dataset in a single pass.

  • Each IOC gets a row with its hit count and a sample match.
  • Matching checks the relevant first-class fields and the raw event, so an indicator is found wherever it appears.
  • ⬇ CSV exports the summary for your report or ticket.
  • Hit rows carry the same ⧉ copy / ＋ add to review actions, so a present indicator goes straight onto the Marks pile.
Ideal for a batch of indicators from a threat-intel report or a previous case — one paste tells you which ones are present and how often.

Sigma

The Sigma tab runs your general ruleset over the EVTX. Field taxonomy is Sysmon/Windows; logsources map to channels/EventIDs:

  • process_creation → Sysmon EID1 and Security 4688 (aliases NewProcessName→Image, etc.).
  • image_load→EID7, driver_load→EID6, network_connection→EID3, registry_event→12/13/14, dns_query→22, ps_script→4104, logon→4624/4625…
  • Rules that filter directly by Channel and EventID (no category) also run.

Load a rules folder on the server, press Run (live progress). Findings are grouped by rule, each expandable to the matching events with a what matched column. Correlation rules (event_count / value_count / temporal) are supported.

Row actions

Every hit row carries an actions cell with three buttons so you never leave the finding to work it:

  • ⧉ copy — the full event JSON to your clipboard.
  • ＋ add to review — marks the event pending in the Marks tab in one click, building your "to review later" pile as you hunt.
  • ⊛ view structured raw — expands the full pretty-printed raw event right under the row, so you read the whole record instead of only the what matched column; click again to collapse.

Rule content (YAML)

When you expand a rule's detections, the panel also shows a collapsible rule content (YAML) block with the full rule — logsource, detection and metadata — so you can see exactly what the rule does next to its hits.

Loading progress. Pointing a tab at a rules folder now shows a progress bar as it parses the rules file by file — in the Sigma tab and in every LOL tab. Running the rules already reported per-rule progress.

LOL tabs

One tab per family: LOLBAS LOLDrivers LOLRMM HijackLibs LOTTunnels. Each tab:

  • asks for its own rules folder (you supply the Sigma rules);
  • shows findings exactly like the Sigma tab — same per-row ⧉ copy / ＋ add to review / ⊛ view structured raw actions and the collapsible rule content (YAML) block;
  • plus a chart of the top indicator by number of events that hit — binary (LOLBAS), driver (LOLDrivers), tool (LOLRMM), DLL (HijackLibs), tunnel tool (LOTTunnels).

Detection is 100% your rules — the app pulls no external datasets.

ATT&CK matrix

Under Sigma & LOL, the ATT&CK matrix turns the case's matched Sigma rules into coverage. It collects the attack.* tags from every loaded rule set (general + each LOL tab) and lays the techniques out as a grid:

  • Columns = tactics; techniques are grouped under their tactic.
  • Each cell is colored by the worst rule level that produced it, and the number is the matching event count.
  • Click a technique to jump straight to a sample event in the Explorer.
Needs rules carrying attack.* tags — techniques only appear for matched rules that declare them, so the matrix reflects your ruleset's tagging, not full ATT&CK.

Lookalike (masquerading)

Finds executed binaries whose name is within a Levenshtein distance of a legitimate Windows/LOLBAS binary (cmd2.exe, svch0st.exe, scvhost.exe). Pick the max distance; optionally also compare the seen binaries against each other. Exact matches (the real ones) are excluded. Binaries are now gathered from all sources — Sysmon Image and Security 4688 NewProcessName — not just Sysmon.

Distance 2 can surface coincidences (e.g. osk.exe vs lsm.exe). Distance 1 is the high-signal setting; always confirm in the Explorer.

Proc tree · Logons · Persistence · PowerShell

These live under the Hunting ▾ parent tab (together with Network, below).

  • Proc tree — rebuilds process trees from Sysmon EID1 and Security 4688 (Sigma process_creation). Processes are linked by ProcessGuid/ParentProcessGuid when present (Sysmon); otherwise by PID (ProcessId/NewProcessId, hex-normalized) within the same host and time order. When both Sysmon and 4688 log the same process the duplicate is merged, and each node shows its source (sysmon / 4688). You anchor it on a process: type a PID, a ProcessGuid or an image name and press «Build tree» — it shows that process's descendants plus its chain of ancestors, instead of loading every tree. When a PID matches several processes (PIDs are reused) you get a small picker to «pin» the exact one; the anchored process is highlighted. Click a node to jump to its context.
  • Logons — the whole authentication family, not just a handful of Security IDs: Security logons (4624/4625/4634/4647/4648/4672), Kerberos (4768/4769/4771), NTLM (4776) and RDP (4778/4779, TerminalServices-RemoteConnectionManager 1149, LocalSessionManager 21/22/24/25). User, source IP, workstation and auth are normalized per source so they line up across event types; failed logons highlighted. Filter boxes narrow by user, type, source IP, workstation, auth and host — combine them to drill in, «Clear» to reset.
  • Persistence — very broad ASEP coverage across Sysmon and native Windows logs: ~65 registry autostart locations via Sysmon 12/13/14 and native Security 4657; the Startup folder and dropped scheduled-task XML (Sysmon 11); services (System 7045 / Security 4697 / start-type 7040); scheduled tasks (Security 4698–4702 + TaskScheduler 106/140/141/200/201); WMI subscriptions (Sysmon 19/20/21 + WMI-Activity 5859/5861); account creation and privileged group changes (4720/4722/4728/4732/4738/4756); and BITS jobs (Bits-Client 3). Each row shows the triggering EventID and host; a client-side filter box narrows by type/detail.
  • PowerShell — 4104 script blocks, reassembled across parts (needs script-block logging in the source host). A search box filters by string: type a substring and only the script blocks whose reassembled text contains it are returned, with the match highlighted. Scripts render as event-like rows (ts / host / user / parts); click one to jump to its context.

Every result row across the Hunting views (Proc tree, Logons, Persistence, PowerShell, Network) carries the same ⧉ copy and ＋ add to review buttons as the Sigma findings — so you can one-click a suspicious process, logon or script block onto the Marks pile without breaking your hunt.

Context lookups (clicking a log to see what surrounds it) are backed by a materialised timeline index, so they stay fast even with hundreds of thousands of events loaded.

Network

Also under Hunting ▾, the Network tab unifies connection telemetry from both Sysmon and native Windows:

  • Sysmon — EID3 (network connections) and EID22 (DNS queries).
  • Windows Filtering Platform — Security 5156/5157 (allow / block) and 5158 (bind).

Protocol and direction are normalized per source so rows from different providers are comparable. Filter by IP/host, port, protocol, process and kind, copy any row's full event JSON with the ⧉ button, and export the loaded rows with ⬇ CSV.

Overview & GeoIP

Case at a glance: counts, events-per-hour, and tops of EventID, Image, host, user, logon type and channel. Source and destination IPs are tagged internal (RFC1918/loopback/link-local) or external; with the free DB-IP Lite database (one button, then offline) you also get country, ASN and ISP, plus Top ISP and Top countries. Click any IP for a detail view (first/last seen, by channel, users, sample events).

Marks (triage)

Mark events pending / TP / FP / dismissed with a note, from the Mark event button in an event's context or by event number in the Marks tab. Marks are stored inside the case .duckdb, so they travel with the case and persist.

The ＋ add to review button on finding, hunting, IOC, Explorer, timeline and context rows marks an event pending here in one click — the fast way to build a "to review later" pile while hunting, then come back to the Marks tab to triage it (set TP/FP/dismissed and add notes).

Report

From the Overview, HTML report / Download report builds a single self-contained HTML file: summary tiles, Sigma detections (collapsible, with matches), LOL findings with charts, persistence, logons, top IPs with GeoIP and triage marks. Everything is collapsed by default so it reads cleanly, and prints well.

AI & MCP

AI (API/local): ask in natural language; the model uses read-only tools (search/SQL/context/stats/timeline). Point it at any OpenAI-compatible endpoint; the key stays in your browser. MCP: expose the same read-only tools to Claude Desktop/Code via python -m winhound.mcp_server.

SQL recipes

-- Office spawning a shell/LOLBIN
SELECT ts, host, image, command_line FROM events
WHERE eid=1 AND source LIKE '%Sysmon%'
  AND lower(parent_image) LIKE '%\winword.exe'
ORDER BY ts;

-- failed logons grouped by source IP
SELECT src_ip, count(*) n FROM events
WHERE source='Security' AND eid=4625 GROUP BY src_ip ORDER BY n DESC;

-- driver loads (BYOVD hunting) with hashes
SELECT ts, host, image_loaded, hashes FROM events
WHERE source LIKE '%Sysmon%' AND eid=6 ORDER BY ts;

-- a value that lives in EventData (extra)
SELECT ts, image, extra->>'TargetObject' AS target
FROM events WHERE eid=13 ORDER BY ts;

-- network connections to a destination
SELECT ts, image, dst_ip, extra->>'DestinationPort' port
FROM events WHERE eid=3 AND source LIKE '%Sysmon%'
ORDER BY ts;

Notes & FAQ

  • Why DuckDB on disk? The case persists (incl. raw and marks), compresses well, and survives restarts; reopen without re-ingesting.
  • No Sysmon? Native logs still work (4688, 4624/4625, 7045, 4698…), just with fewer fields (no hashes/image_load).
  • GeoIP offline box? Download fails only reach db-ip.com; internal/external tagging always works without a base.
  • Rules? You bring your own Sigma (general + one folder per LOL tab). The app ships none.
